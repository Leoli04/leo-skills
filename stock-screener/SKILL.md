# Stock Screener · A股粗筛（12 类）

## 与 stock-analyzer 的分工

| | stock-screener（本 skill） | stock-analyzer |
|---|---|---|
| 阶段 | **粗筛**，从 5,100 只压到 4~120 只 | **深评**，逐只出完整报告 |
| 产出 | 候选池看板 | 单标的投资分析报告 |
| 结论性质 | **初筛，深度不足** | 折现＋概率加权＋胜率 |
| 能否作加仓依据 | ❌ **绝对不能** | ✅ 可以 |

**衔接方式**：本 skill 出候选池 → 用户选型 → 走 stock-analyzer 的 10 步流水线。
两者的判据同源（都出自方法论 v2.3），但**本 skill 只做可横截面量化的那一部分**。

---

## 铁律

1. **初筛结论必须显式声明「深度不足」**，不得与深度覆盖结论并列。
2. **本 skill 的输出绝不可作为加仓依据**，只能作为「值得投入深度研究时间」的候选。
3. **横截面筛选只覆盖可量化判据**。估值锚归类、单季环比拆解、经营现金流质量、
   分部收入结构、景气档位、筹码结构、催化传导 —— **这些一律没做**，必须在
   深度评估阶段补齐。
4. **「周期陷阱」是排雷池，命中即风险提示，不作候选**。
5. 剔除候选时**必须写客观理由**（哪个判据不达标），禁用「已分析过」「超目标价」。

- `industry_cache.json` —— 行业分类缓存，存在则不再联网

- `scripts/box.py` —— 箱体形态计算（拉 52 周周K），可单独跑：
  `python box.py sh600887 sh600519`

## 12 类筛选条件

按「赚什么钱」分四组。`kind` 决定看板标签与是否可作候选。

### 一、赚结构改善的钱（core）

| 类型 | key | 核心判据 | 命中量级 |
|---|---|---|---|
| 严格前奏池 | `prelude` | 利润弹性≥3x ＋ PE/PB十年分位双<30% ＋ 自由流通≤100亿 ＋ ROE>12% | **4~5** |
| 质量宽口径 | `quality` | PE/PB分位<35% ＋ ROE>13% ＋ 毛利率>25% ＋ 归母正增长 | ~41 |
| 成长股 | `growth` | 营收3Y复合>15% ＋ 利润3Y复合>20% ＋ 毛利率>35% ＋ PE<60 | ~66 |
| 小盘成长 | `smallgrowth` | 市值30~100亿 ＋ 利润3Y复合>25% ＋ ROE>10% ＋ 自由流通<80亿 | ~37 |

### 二、赚估值修复的钱（core）

| 类型 | key | 核心判据 | 命中量级 |
|---|---|---|---|
| 超跌反弹 | `oversold` | 52周跌>25% ＋ 现价处52周区间35%分位以下 ＋ PE分位<25% | ~105 |
| 低估值 | `value` | PE<15 ＋ PE/PB分位双低 ＋ ROE>10% ＋ 归母正增长 ＋ 市值>100亿 | ~55 |
| 困境反转 | `turnaround` | PB<2 ＋ ROE 3~12% ＋ 年内跌 ＋ 仍分红 ＋ 负债率40~75% | ~120 |

### 三、赚现金流的钱（core）

| 类型 | key | 核心判据 | 命中量级 |
|---|---|---|---|
| 高股息 | `dividend` | 股息率TTM>3% ＋ PE/PB分位双<40% ＋ ROE>12% ＋ 市值>100亿 | ~66 |
| 白马 | `bluechip` | ROE 15~30% ＋ PE<25 ＋ PE分位<50% ＋ 日振幅<4% ＋ 股息>2% ＋ 市值>300亿 | ~12 |
| 周期底部 | `cyclebottom` | PB分位<25% ＋ 负债率>55% ＋ 年内跌>10% ＋ 归母正增长 | ~27 |

### 四、交易型（trade，⚠️ 非常规持仓逻辑）

| 类型 | key | 核心判据 | 命中量级 |
|---|---|---|---|
| 网格交易 | `grid` | 流动性粗筛 ＋ **箱体形态**（振幅 12~60%、穿越中轴≥4 次、单边性<55%） | ~9 |

### 五、排雷池（danger，⚠️ 命中=风险，不作候选）

| 类型 | key | 核心判据 | 命中量级 |
|---|---|---|---|
| 周期陷阱 | `value_trap` | PE分位<20% **且** PB分位>60% | ~10 |

## 三个必须知道的局限

### ① 网格池的判据是箱体形态，不是波动率

**横截面财务条件筛不出网格标的** —— 网格要的是「价格长期在某个箱体里来回晃」，
这是**时间序列特征**，必须拉 K 线算。因此网格池分两层：
1. `screen.py` 的横截面条件只做**流动性粗筛**（成交额>5亿、换手 0.2~12%、PE<30、PB分位<50%）
2. `box.py` 拉 **52 周周K** 算箱体，二次过滤只留 `good` 评级

箱体判据（三个维度缺一不可）：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 箱体振幅 | 12% ~ 60% | 太窄扣完手续费没赚头，太宽区间失控 |
| 穿越中轴次数 | ≥ 4 次 | 价格真在箱内反复来回 |
| 单边性 | < 55% | 净位移占箱体宽度，越小越像箱体 |

**⚠️ 不要用随机游走折算的波动率**（如 `(高−低)/低 ÷ √52`）当网格判据。
它假设价格无界游走，会严重低估箱体宽度 —— 伊利实测折算出来仅 2.8%，
而真实箱体是 25.3%。

**⚠️ 旧版判据是错的**（已修）：`RangePCT > 2`（当日振幅）筛的是「今天情绪激动」，
会把伊利（五粮液、海尔这类当日振幅仅 1% 的大盘票）全部误杀；
`TurnoverRate > 1` 同样卡死大盘蓝筹。现已改为流动性下限 + 箱体过滤。

**52 周窗口是实测最优**（对比 52/78/104 三档）：104 周会把 2021 结构性重估期
算进箱体，导致白酒、消费股全被误判 wide；78 周仍偏宽。52 下伊利 25.3%→good、
海康 36.9%→good、茅台 36.2% 但只穿越 3 次→trend（准确，近期确在单边下行）。

**怎么用**：格距取箱体振幅的 1/3；现价分位 <30% 以买为主、>70% 以卖为主、
中间可双向挂。**箱体是后验统计，不代表未来仍成立** —— 须检查是否有基本面
变化打破箱体（如伊利 2026 年就跌破了 2025 年的 26~31 箱体）。

### ② 单一强赛道会染满整个池

实测：`growth` 池 66 只里，TOP6 有 5 只是半导体存储（江波龙归母 +71528%）。
这不是筛错了，是**行业性 vs 公司自身**问题 —— 强赛道上所有公司一起涨。

**缓解**：`growth` / `smallgrowth` / `value` / `turnaround` / `cyclebottom`
五个池设了 `ind_cap`（同行业限 3~4 只），靠行业分类去重。
行业数据走新浪接口（详见下文数据源），覆盖率约 75%；**未覆盖的股票不参与限流**，
看板里行业列显示 `-`。看到 `-` 偏多时，仍需人工检查候选的行业集中度。

### ③ 排雷池比找机会池更该看

`value_trap` 命中的是「PE 低是因为盈利在顶」的教科书陷阱。
实测会捞出洛阳钼业、国城矿业、四川长虹这类（PE分位 1~8% 但 PB分位 77~85%）。
**先把排雷池看完，再看找机会池** —— 避免把假便宜当真便宜。

## 数据源与字段陷阱（实测，照抄勿试错）

### 筛选接口只回传「参与筛选的字段」

要让某个判据出现在看板里，**必须把它写进筛选条件**。用恒真条件（如 `> -999`）
纯为取值，勿删 —— 见 `screen.py` 的 `_SHOW` 常量。

⚠️ **`_SHOW` 必须包含看板每张表固定展示的字段**：
`ClosePrice` / `ChangePCT` / `TotalMV` / `NegotiableMV`。
实测遗漏 `NegotiableMV` 会让 6 个池的「自由流通」列**整列为空**，
而它恰是看流动性最该看的一列。改 `_SHOW` 后务必复查：

```bash
python -c "import json;d=json.load(open('candidates.json',encoding='utf-8'));\
need=['ClosePrice','ChangePCT','TotalMV','NegotiableMV'];\
print([k for k,r in d.items() if r and [f for f in need if f not in r[0]]])"
```

### ⚠️ 周K 线的 scale 参数：240 是日线，1200 才是周线

新浪 `CN_MarketData.getKLineData` 的 `scale`：
- `scale=240` → **日线**（曾误当周线，算出「Q4 有 43 周」的荒谬结果才察觉）
- `scale=1200` → 周线

别用 `datalen` 猜：800 根周线 ≈ 15 年，800 根日线 ≈ 3 年。

### 行业字段不能用于表达式筛选

`SW1Name > 0` 返回**空数组**，`SW1Name = '食品饮料'` 同样为空，
`IndustryName > 0` 也空。BI 类字段只支持展示，不进筛选表达式。

### ⚠️ 行业数据源：用新浪，不要用东财

东财 `push2` / `82.push2` / `7.push2` **三个域名全部实测 `RemoteDisconnected`**，
冷却 90 秒不恢复（逐股查 24 只失败 22 只）。**别再试东财。**

新浪两步可用，实测稳定：

| 步骤 | 接口 | 产出 |
|---|---|---|
| 1 | `vip.stock.finance.sina.com.cn/q/view/newSinaHy.php` | 49 个新浪二级行业 node |
| 2 | `.../q/view/newFLJK.php` | 84 个证监会门类 node |
| 3 | `.../Market_Center.getHQNodeData?node=<key>&num=200` | 该板块成分股 |

解析要点：返回是 `var S_Finance_bankuai_xxx = {...};` 需正则剥壳；
字符集是 **GBK**；两套源**合并使用**（门类优先、细分补缺）——
单用第1 套只覆盖候选池 61%，合并后 75%。133 个板块约 27 秒。

### ⚠️ 行业未知 ≠ 同一行业

限流时**必须**把「查不到行业」的股票**放行**，不能归到同一个「未分类」桶里限流。
否则一堆互不相关的公司会被当成同一行业误剔 —— 实测「成长股」池因此被砍掉 46 只，
改对后只剔3 只。见 `apply_industry_cap()`。

### 字段名（沪深）

| 含义 | 字段名 |
|---|---|
| 估值分位 | `PE_TTMPct10Y` / `PE_TTMPct10Y` / `PB_LFPct10Y` / `PB_LFPct10Y`（**十年窗口**） |
| 市值 | `TotalMV`（总）/ `NegotiableMV`（流通）**单位是元** |
| 增速 | `TORGrowRate`（营收同比）/ `NPParentCompanyYOY`（归母同比） |
| 复合增速 | `ORComGrowRate3Y` / `NPPCCGrowRate3Y` |
| 盈利质量 | `ROETTM` / `GrossIncomeRatio` / `DebtAssetsRatio` |
| 价格位置 | `Chg52W` / `ChgYtd` / `Week52High` / `Week52Low` / `HistHigh` / `HistLow` |
| 交易属性 | `RangePCT`（当日振幅）/ `TurnoverRate` / `TurnoverValue` |

多条件 AND **必须** `intersect([...])`，不支持 `&` / `&&` / `AND`。
PE/PB 筛选取值必须排除负值（`PE_TTM > 0`）。

## 生成 HTML 的硬约束（本项目已踩 4 次同类事故）

**「结构检查全绿但页面全空」在本项目发生过 4 次。零 JS 页面必须截图验收。**

1. **CSS 只能在 `<style>`，绝不能写进 `<script>`**。裸 CSS 被 JS 引擎当表达式
   解析后整块丢弃 → `:has()` 规则消失 → 所有 section 保持 `display:none`
   → **页面全空**。而 div 配平、规则计数、占位符检查**全部通过**。
2. **radio 必须与 label 同在**。删掉 radio 元素后 `:has(#x:checked)`
   永远不成立 —— 结构检查看不出来。
3. **`.active` 类绝不能写 unconditional `display`**（优先级高于 `:has()`，
   会让首节常驻、切 tab 时两节同显）。
4. **验收方法**：复制 HTML 注入脚本设 `radio.checked = true`，
   `chrome --headless=new --screenshot=out.png`（**路径必须 Windows 绝对路径**，
   相对路径被拒 `0x5`），逐 tab 截图。
   **三张图字节数完全相同 = tab 没切换。**
5. `screen.py` 内置了 4 条断言（radio 数 / has 规则数 / style 位置 / div 配平），
   但**断言不能替代截图** —— 只挡最粗的那类错。

## 扩一类新筛选的步骤

1. 在 `PROFILES` 里加一项，写全 `name / kind / money / desc / logic / order / cond`。
   `logic` 字段会显示在看板上，**写清判据与禁用尺子**，别只写一句口号。
2. 条件末尾追加 `_SHOW`（否则看板该列空白）。
3. 需要行业去重就加 `ind_cap=N`。
4. `PROFILE_COLS` 里指定展示列（从 `COLS` 的 `_base/val/qual/grow/price/trade` 里挑）。
5. **先 `--type 新key` 单跑验证命中量级**，太宽（>150）就收紧，太窄（<3）就放松。
6. 跑 `--refresh` 全量，**截图逐 tab 验收**。

**禁止**：在 `build_html` 里加 unconditional `display` 规则；把 CSS 写进 `<script>`。
