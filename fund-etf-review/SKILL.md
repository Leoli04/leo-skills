# 基金/ETF 方法论文档评估与复评

## 概述

本 skill 固化了一套对「基金/ETF 挑选指南」类方法论文档（HTML/MD）的评估流程：数字口径复算 → 权威判据完整性 → 一致性 → 工程规范 → 分级清单 + 评分。支持多轮迭代复评（用户改完文档后说「再次评估」），直到定稿。评估过程只输出结论与问题清单，**不修改用户文档**——除非用户明确要求代改。

## 工作流（首轮评估）

### Step 1 通读全文

完整读取被评估文档（HTML 用 Read 直接读，注意 HTML 转义实体如 `&lt;`）。记录文档定位（方法论/研报/清单）、成文时点、约定符号（✅/❌/⚠️ 的语义）。

### Step 2 数字口径复算（核心步骤）

对文档中**每一条可计算的数字断言**，用脚本或手工 Python 复算，并核对三要素：数值、假设口径、方向性表述。已固化的复算锚点（详见 references/checklist.md「数字参考值」）：

- 费率复利拖累：`scripts/verify_math.py fee-drag 0.015 0.002 --years 20` → 0~8% 收益假设下 20 年终值差约 27.5%~30%。文档若写「约 25%」= 偏低 ❌；若不注明收益假设 = 口径不严谨 ⚠️。
- A/C 类盈亏平衡期：`scripts/verify_math.py ac-breakeven 0.0010 0.0020` → 申购费÷销售服务费 ≈ 0.5 年（一折 0.15% 则 0.75 年）。文档只给「<1 年选 C」结论不给公式 = ⚠️，正确写法是给公式 + 执行兜底（「拿不准就 >1 年选 A」）。
- 其余断言（清盘触发线、联接基金仓位、T+0 品种范围等）对照 checklist.md 的法定/行业口径逐一核验。
- **方向性表述也要验**：如「收益越低差距越大」——用收益参数扫描验证方向是否成立。

### Step 3 对照权威判据查完整性

读取 references/checklist.md，按其中「文档必备模块清单」逐节核对：ETF 六项筛选、场外份额规则、主动基金四看+硬否决+一触发器、组合纪律、定投纪律、坑清单。缺失实质条款（如「经理离任触发器」这类逻辑闭环缺口）记 ❌；缺失附注类内容（联接基金、T+0）记 💡。

### Step 4 一致性与工程规范

- 同页矛盾：同一事实在两处表述冲突（如表格列银行为渠道、坑清单又否决银行渠道且无交叉引用）。
- 口径唯一性：同一数字全篇只允许一个写法（本项目方法论一贯要求）。
- 标题计数与正文实体数是否相符（「四看、两否决」但表内有 4 处否决项 → 措辞级问题）。
- 工程规范：零依赖单文件 HTML（无 JS/无 CDN/内联 CSS）、新增内容不得引入新外部依赖、文件命名符合本项目报告命名规范（方法论文档属非个股报告，不套 41 红线自检）。

### Step 5 同指数/同类替代品对比（必做）

单只基金的评估**必须列出更低费率的替代载体**，否则评估不完整：

1. 用东财基金搜索接口（`fundsuggest.eastmoney.com/FundSearch/api/FundSearchAPI.ashx?m=1&key=<标的名>`）召回同标的名下全部产品；搜索词多试几个（如「食品饮料」「食品饮料联接」「国证食品饮料」），防止漏掉联接基金与 C 类份额。
2. 逐只抓 F10 概况页（`fundf10.eastmoney.com/jbgk_<code>.html`），解析「基金简称 / 跟踪标的 / 管理费率 / 托管费率 / 销售服务费率 / 净资产规模」。
3. 按「跟踪标的一致性」分组：同指数产品（可直接替代）排前；成分高度重叠但编制方不同的指数标注口径差异，提示切换前核对成分。
4. 核查本基金的 A/C 类完整结构（C 类销售服务费 + 规模），A/C 对比写进替代品表；漏查 C 类属实质错误，发现后须在报告中出「修正声明」。
5. **场内/场外双通道必须都覆盖**（缺任一通道 = 报告不完整，用户会退回）：
   - 场内：同指数/重叠指数 ETF。
   - 场外：目标 ETF 的**联接基金**（搜索词加「联接」）——无券商账户/定投场景的承接载体。ETF 本身没有联接时必须明说（如 159843 无联接），并给成分高度重叠指数的联接作为次选；结论写明「同指数低费载体场内/场外各是谁」。
   - 联接基金费率结构 = 目标 ETF 费率之外**不额外叠加**联接层管理托管费（实测：159736 ETF 0.60% ↔ 001631 联接 0.50%+0.10%=0.60%），C 类联接另加销售服务费（013126 = 0.60%+0.30%=0.90%）；「0.60% + 联接费率」这类含糊写法 ❌，必须给核实后的总费率。
6. **费率之外必须补业绩与风险维度**（只比费率 = 对比不完整，用户会退回）：
   - **统一窗口**算各替代品：近 1 年收益（官方 syl_1n）+ 近 3 年累计/年化、最大回撤、年化波动、Sharpe（rf 取 1.5%）、Calmar——全部从净值序列自算，160222 的结果须与官方口径交叉验证。
   - 数据源：`fund.eastmoney.com/pingzhongdata/<code>.js` 批量拉候选基金净值序列；持仓走移动端接口 `fundmobapi.eastmoney.com/FundMNewApi/FundMNInverstPosition?FCODE=<code>&deviceid=Wap&plat=Wap&product=EFund&version=6.2.8`（字段 GPJC 名称 / JZBL 占比%，报告期在 `Expansion`）。
   - **持仓结构对比**：前十大占比 + 与本基金前十大重叠度（同指数应 9~10/10）；联接基金直接持股权重极低（主持仓为目标 ETF），须写「穿透后 = 目标 ETF」而非误报「无持仓」。
   - 解读三件套：全行业 Sharpe 同负时比「谁跌得少」；年化差拆「费率差 + 跟踪/现金拖累」；持仓同构 → 差异全来自费率与仓位结构（「换载体是纯升级」类结论）。
7. 输出对比表：代码 / 名称 / 跟踪指数 / 总费率 / 规模 / 通道（场内·场外·联接）/ 对比本基金，场外行集中在场内行之后；对每组费率差跑 `verify_math.py fee-drag` 量化 20 年终值差；业绩/风险维度单独成表（指标行按基金列，最优值标绿、本基金最差项标红）。

### Step 6 生成 HTML 报告（必做）

评估结论必须落成报告文件，不允许只停留在对话输出：

- 规范：零 JS、无 CDN、内联 CSS、浅底深字研报风；净值曲线用内联手绘 SVG（标注峰/谷/现值与回撤）。
- 命名：`<标的简称>(<代码>)_基金评估_<YYYY-MM-DD>.html`，日期=数据截止日，简称内禁 `( ) - _ /` 空格。
- 章节骨架：结论框 → 基本盘 → 六项判据逐项核对 → 业绩与回撤（表+SVG） → 费率拖累量化 → **替代品对比表** → 操作口径 → footer（数据来源+时点+复算口径）。
- 若本轮修正过上轮结论，报告内必须有独立的「修正声明」块，不得静默改写。
- 生成脚本落地 `.tmp/`；模板拼接**用 `{{TOKEN}}` 占位符 + `str.replace()`，禁用 `%` 格式化**（CSS 百分号与格式化字符冲突，曾致模板中断）；替换后必须 grep 校验无 `%s`/`{{` 残留，再做结构校验（DOCTYPE/无 script/外链/div·table·tr 配平/SVG polyline/关键标注词）。
- Edge 无头在部分会话被 SIGTERM：结构校验用 Python 兜底，视觉确认交给资料库预览。

### Step 7 上传资料库（必做）

1. 目标节点（已固化）：个人空间 `lWmChDNEl28HPp3VjuY5W7` → 「投资」文件夹 `xcJDrLzCXZPe5NwefUjsl4` → 「基金和ETF」子文件夹 `ujlYAui5OmAlkvfEjReBOW`。目标节点不存在时先列节点确认再创建，不凭记忆用旧 id。
2. 上传：`page/import_html.py <本地路径> --parent-id ujlYAui5OmAlkvfEjReBOW --space-id lWmChDNEl28HPp3VjuY5W7`（注意路径是**位置参数**，不是 `--file`），成功输出 `KS_IMPORT_OK {...url...}`，把 url 转述给用户。
3. **报告修订 = 原地覆盖**：已上传过的报告更新后改传 `--node-block-id <节点id>`（不传 `--parent-id`），节点 URL 与标题不变、不产生重复条目；资料库不支持删除节点。
4. 报告命名与资料库节点标题同格式。

## 输出格式（对话回复）

结论先行，按此结构输出：

1. **一句话总评 + 分数（X/100）**
2. 分级问题清单表格：`❌ 实质问题 / ⚠️ 口径不严谨 / 💡 可选润色`，每项注明位置（行号/节名）、问题、建议修法
3. ✅ 已达标项简表（简短，防止下轮误改）
4. 一句话总结（改哪些能到多少分）

## 复评模式（用户说「已修改，再次评估」）

1. 重新完整 Read 文档——禁止凭记忆评估，文档必须重读。
2. 逐项核对上轮问题清单，输出「上轮问题 → 修改情况 → 评价（✅ 落实/❌ 未落实/⚠️ 部分落实）」表格；对修改后的数字重新复算，不允许沿用上轮结论。
3. 检查**无新引入问题**：新增内容的事实准确性（逐条核验）、新增 CSS class 是否存在、是否引入外部依赖。
4. 上轮标记为「可选/不必改」的项，本轮仍只作观察项报告，不升级为问题。
5. 更新评分；全部 ❌/⚠️ 清零且无新问题 → 给出「建议定稿」结论。
6. 评估对象是具体基金时（非方法论文档）：复评同样必须走 Step 5~7 全流程（替代品重查+报告重生成+资料库更新）；若上轮结论有误，报告内加「修正声明」块。

## 评分锚点

| 分数 | 状态 |
|---|---|
| 80–85 | 框架与红线达标，存在数字口径错误或实质缺失 |
| 90–94 | 实质问题清零，残留口径表述或可选润色 |
| 95–97 | 全部问题清零（措辞级观察可留），建议定稿 |

## 红线

- 不预测基金未来收益；评估结论不构成投资建议。
- 只核验方法论文档的口径与逻辑，不借评估之口输出个股/基金买卖推荐。
- 不擅自修改用户文档；评估输出问题清单，由用户决定是否修改。
- 涉及具体基金实时数据（净值/排名/持仓）时不在本 skill 范围内凭训练数据回答——走 neodata-financial-search 实时查询。

## 数据源降级路径（已实测）

neodata 主数据源不可用时（本地代理 502 / 上游拒绝连接 os error 10061），按以下顺序降级，且**必须在报告与回复中标注来源与时点**：

1. 东财天天基金公开数据（本 skill 实测可用）：
   - `fund.eastmoney.com/pingzhongdata/<code>.js` — 名称/费率/阶段收益（syl_1n 近1年、syl_6y 近6月、syl_3y 近3月、syl_1y 近1月）/经理/净值全序列/同类排名百分位（`Data_rateInSimilarPersent`）。**解析坑**：文件带 BOM；变量定义同行相邻，正则须以 `;\s*(?:/\*|var )` 为边界而非行尾。
   - `fundf10.eastmoney.com/jbgk_<code>.html` — 全称/类型/成立/规模/管理·托管·销售服务费/跟踪标的。
   - `fundsuggest.eastmoney.com/FundSearch/api/FundSearchAPI.ashx?m=1&key=<关键词>` — 基金搜索（`Datas[]` 数组，`CATEGORY==700` 为基金）。
2. 回撤/各期收益用单位净值序列自算：**先确认拆分/分红事件（`unitMoney` 非空点），拆分之后才是一段无失真序列**；算完必须与官方 `syl_*` 阶段收益交叉验证（差 <0.5pct 为通过）。
3. A 类之外的份额（C/E）必须单独搜索确认存在性，不得凭 pingzhongdata 单文件断言「无 C 类」。
4. Edge 无头渲染在部分会话不可用（SIGTERM）→ Python 结构校验兜底（DOCTYPE/无 script/无外链/标签配平/SVG polyline/无占位残留）。
