# Phase 11 台账 · 操作细则

> 配套 `SKILL.md` 的 Phase 11。SKILL.md 里保留触发时机、四步流程命令块与交付前自检；**本文件是 overrides 纪律、归并口径、目录约定、上传后归档步骤与脚本踩坑固化**。以下情况必读本文件：① 填写 / 更新 overrides；② 归并时节点匹配有歧义；③ 上传新版后有旧版要归档；④ 要改 `assets/watchlist/` 下任何脚本。

## 持仓与计划 Tab（2026-10-16 起，render 自动生成）

manifest 顶层 `positions` 段记录用户**实际持仓**（每条含 `code / name / strategy(做T底仓|波段|利润底仓…) / opened / shares / shares_total / cost 或 cost_label / note / plan[[环节,动作]...]`）→ 渲染为「持仓与计划」Tab：概览表（点击行跳转对应计划卡）→ 汇总条 → 各持仓计划卡；现价与观察池行情联动。**仓位变动只需改 `positions` 段再跑 ③④**。观察池内实际持仓标的徽标固定「持仓中」（tooltip=op 摘要）；报告原文「操作」字段仍按压缩文案显示（如茅台「持有中」），两者口径不同属预期。**持仓判定与报告判定相互独立**（康比特判定「不买 · 观望」但持有利润底仓），不得互相覆盖。⚠️ 库端台账若含「持仓与计划」Tab，**一律不要用本地整页渲染覆盖上传**（本地整页渲染无法产出该 Tab，须走库端行级补丁路径）。

## 台账命名与现价刷新口径（2026-10-16 用户裁定）

- **命名**：文件名与资料库节点标题 = **最近刷新日** `投资观察池台账-<YYYYMMDD>.html`（当日有刷新就当日命名）；页头「报告数据时点（`--asof`）」仍取池内最新报告 asof，与「现价时点（`--px-asof`）」分列，两个时点并存属预期。
- **`refresh_prices.py`（可选）**：把 `ledger_final.json` 的现价刷成实时行情（腾讯 `qt.gtimg.cn`，A 股 / 港股 / 北交所），产出 `ledger_live.json` 并记下行情时点（渲染时用 `--px-asof` 取该时点）。**只改现价（顺带重算潜在空间与距买点），期望价 / 买入胜率 / 观察买点一律不动** —— 它们锚定报告写作时的基准价，故页头须标注「现价时点」，胜率列标「报告口径」。不加此步则渲染时不传 `--px-asof`，页面回到纯报告快照口径。

## overrides 纪律（对应「零编造」红线）

- 只填**自动抽取不到或抽取有误**的字段，且每个值必须在报告原文中核对过（结论横条 / 结论建议节 / 页头指标卡）。
- 抽取值与原文不符时**按原文更正并把更正写进 overrides**，不得让错值留在表里。
- 报告确实没给的字段留空，**不估算、不用其他报告的值补**。
- B 类报告的评级口径 / A 类无结论横条的报告（旧版模板）走 overrides，`build_watchlist.py` 会在输出里列出「无结论横条(需人工核对)」清单提醒逐份核。
- **`alert`（可选字段｜行情更新提示）**：报告出具**之后**发生的行情事实（含与报告结论**方向相反**者，典型：跌破报告自己写死的退出价位）。写一行大白话，自带日期、触发条件与规定动作。两种落法：**①只提示不改数**（默认）——judge / px / exp / win / obs 一律保持报告快照，卡片上的现价 / 期望价 / 胜率 / 报告日期与条内行情不一致是刻意的；**②维护为最新价**——经用户确认后，把 `px` 一并覆盖为报告之后的最新收盘价（值取自当日收盘，`src` 写明来源与口径），则潜在空间、距买点随新价重算（分母变了），而 exp / win / judge / **报告日期仍是报告原值**，条首句须写明「现价已维护为 ……」以免读者误认现价时点。渲染层把它做成卡片上的琥珀条（`zcard__alert`），并在页内「口径与设计说明」里单列一条解释；再用红绿会与涨跌语义抢占。**没有这类行情事件就不要写这个字段**，不要拿它当备注栏。

## 上传后归档（收尾必做 · 有历史版本时）

用户的硬要求：**新版上传后，若「个股报告」里同标的存在新老两份，必须把老报告移入「旧版归档」**，库内只留最新一版。资料库**不支持删除页面 / 文件夹节点**，只能用 `move-node` 移位。

**单个标的**（刚上传完那份，逐标核对用）：固定动作，顺序不可调换：

1. **上传新版** —— `import_html.py --space-id <space_id> --parent-id <report_folder_id>`，落在「个股报告」内（见 SKILL.md「交付」）。
2. **重扫一次** —— **不能复用 Phase 0a 的结果**（上传后节点集合已变，新节点此刻才出现）：
   ```bash
   python <skill>/assets/lib_reports.py scan --manifest <工作目录>/watchlist_manifest.json \
     --code <代码> --name <简称>
   ```
   输出 `MULTI_VERSION` = 同标的 ≥2 版并存，**必须归档至只剩 1 版**。
3. **归档旧版** —— 用上一步打印的 `TO_ARCHIVE` 清单逐个移动：
   ```bash
   python <skill>/assets/lib_reports.py archive --manifest <工作目录>/watchlist_manifest.json \
     --node-id <旧版 node-id> [--node-id <...>] [--dry-run]
   ```
   幂等：`parentId` 已在归档夹内的节点自动跳过（`[SKIP ]`），可安全重复执行。先 `--dry-run` 看清要动哪些再实跑。
4. **回扫核对** —— 再跑一次 `scan`，期望结果是 **`HISTORY_FOUND`（只剩最新一版）**；仍是 `MULTI_VERSION` 说明还有漏网，回到第 3 步。这一步是**唯一可靠的验收**，不要靠 `move-node` 的返回判断。
5. **改标题（必要时）** —— `move-node` **不改节点标题**：标题只在首次创建时由 `--file-name` 决定，覆盖上传与移动都不会变。若标题里的日期与内容日期不一致，另调 `space.workspace.rename-node --node-id <id> --title "<标准格式>"` 改齐。
6. **只动资料库，不动本地** —— 归档只针对库端节点；工作区里由资料库拉回的历史镜像文件**保持原样**，不删除、不改名（那是别的会话的产物）。
7. **记账** —— 把「Phase 0a 检索 → 模式确认 → 上传 → 归档结果（含被移动的 node-id）」逐条写进当日 memory 日志。

> 边界：`TO_ARCHIVE` 里若出现「与最新版**同日、仅报告类型不同**」的条目（如「投资分析报告」与「净利率收敛空间测算」），那可能是**互补文档而非新老版本** —— 脚本会标 `⚠` 提醒。这种情况下**归档前必须人工判断**：确属互补则保留，确属取代才移动。脚本只给建议清单，不代替判断。

## 全量盘查（批量清理用 · 不能逐标扫时）

用户说「查一下库里重复的 / 老的报告，归到归档去」这类**枚举式需求**时，逐标跑 `scan` 不现实（要先把全库标的列一遍）。改跑一次 `audit`：

```bash
python <skill>/assets/lib_reports.py audit --manifest <工作目录>/watchlist_manifest.json
```

它把「个股报告」内**全部节点按标的归组**（有代码用代码；无代码的节点若其名称在全库只对应一个代码，则借名归组，打印时标 `← 借名归组`），一次给出：

| 输出段 | 含义 | 动作 |
|---|---|---|
| `--- 需要归档的标的（N 组）---` | 每个多版本组，逐条标 `KEEP` / `ARCHIVE` | 按 `待归档 node-id` 清单跑 `archive` |
| `--- ⚠ 无法归组 ---` | 标题里既无代码、名称也解析不出 | 人工看，必要时 `rename-node` |
| `--- ⚠ 完全同名 ---` | 同一标题出现 ≥2 次（疑重复上传） | 人工比对后留一版 |
| `AUDIT_RESULT: CLEAN` | 没有任何多版本组 | 无事可做，收工 |

结论只需看两行：`AUDIT_RESULT: NEEDS_ACTION` 时把脚本直接吐出的 `待归档 node-id` 清单喂给 `archive`；`CLEAN` 即已完成。**验收同样以回扫为准** —— 归档后再跑一次 `audit`，必须变 `CLEAN`（不看 `move-node` 返回值）。只读，可反复跑。

## render_watchlist.py 配色硬约束（改配色 / 改档位前必读）

- 渲染零依赖离线 HTML 台账（v2「决策驾驶舱」：masthead + 自动结论条 + 5 张 KPI + 全池总览〔潜在空间分布柱 + 赔率矩阵 + 三桶构成条〕+ 四分区台账〔A 区贴近买点用卡片、B/C/D 区用表格〕+ 复核时间轴 + 口径与设计说明）。涨红跌绿；**判定三桶刻意避开红绿**（回避 = slate / 观察 = indigo / 减持 = amber），红绿只承担潜在空间正负一种语义。支持搜索、三键排序、分区折叠、快速筛选 chips，交互全部内联 JS，零 CDN。
- **配色三档**：标准（默认，卡面 `#f8fafc`）/ 护眼（暖纸低蓝光，卡面 `#f7f4ec`）/ 深色（夜间，卡面 `#1a1f28`）。切换器在 masthead 右上角，选择存 localStorage 键 `wl-theme`，`<head>` 内联脚本提前套用以防深色档闪白（FOUC）。三档共用同一套语义色，定义在 `:root`（= 标准档）/ `:root[data-theme="eye"]` / `:root[data-theme="dark"]`；标准档无独立覆盖块，`data-theme="std"` 时继承 `:root` 即该档效果。旧键值 `soft` 由 `<head>` 预置脚本映射为 `std`（首版「柔和 / 标准 / 深色」中的纯白档已并入标准档）。
- 新增语义变量（2026-10-09 三档改造时补）：`--mast-eyebrow` / `--mast-glow` / `--tt-ink` / `--tt-on` —— masthead 上的 eyebrow 文字、右上角光晕、切换器按钮的常态与选中字色。原先这四处是硬编码，护眼档（暖褐头部）下蓝色会与整体暖调冲突。
- ⚠️ **改配色时的硬约束**：任何"实心块背景"或"热力/弱化色"都必须走语义变量，**不可直接拿 `var(--ink-900)` 当背景**——深色档下 `--ink-900` 是近白色，配 `#fff` 文字会成白底白字。已备好的语义变量：`--solid`/`--on-solid`（排序选中态）、`--brand-fill`/`--on-brand`（chip 选中态，与当文字用的 `--brand` 分开取值，否则深色档浅蓝底白字只有约 2.5:1）、`--heat1~3-bg`/`--heat1~3-ink`（赔率矩阵）、`--dot-off`/`--dot-low`/`--dot-mid`/`--dot-mid-ink`（胜率点阵）、`--chg-bg`/`--chg-ink`（变化高亮）、`--mast-a/b/c`（头部渐变）。新增档位时对照这套清单逐项给值。

## 踩坑固化（改脚本前必读，每一条都是实测撞出来的）

1. **键值对匹配禁用 `in`** —— `vb-k/vb-v` 面板里有用 `in` 会误配的键（备注键「（对现价 −1.0%…）」会让「现价」拿错值），必须精确相等 → 前缀匹配两段式。
2. **`strip()` 必须先解码 HTML 实体再剥标签** —— 反了的话 `&lt;div` 会在剥标签之后变成假标签残留进正文。
3. **同一报告可能有多个 `class="verdict-bar"`**（CSS 定义里、JS 模板里、页头副本），只有**后接 `class="nav"` 导航栏**的那个是页面真实横条，且要**取最后一个**；用 `rfind('</style>')` 定位会漏掉真面板。
4. **导航锚点是 `class="nav"` 而非 `<nav>` 标签**（模板输出的是 `<div class="nav">`）。
5. **取现价按可信度排序**：`vb`键值对 → `基于 2026-10-09 盘中价 92.73 元` → `23.83 现价（元）` → `现价 116.25 元` → `收盘价（2026-09-30）74.49`。**禁止**用「现价」二字直接抓后面第一个数字（会被「对现价 −7.85%」截走）。
6. **判定字段要截断**：判定后面常紧跟口径说明（`加权期望价` / `现价` / `买入门槛` / `仓位` / `元`），在**空格 + 字段名**处截断；但「持有底仓 / 现价不追高」里的「现价」是判定的一部分，不能一律切。
7. **归桶分两步，缺一不可**：①先在「判定首词」（`/ · （` 等分隔符之前的部分）内判 `不买|回避` → N、`减持` → S、其余 → H——只按全文包含判断，「持有 / 观望（暂不买入）」会被括号里的否定词误判成 N；②首词里若无结论词，再在**首词内部**检索第一个命中的结论词，否则「当前价位回避新建仓」这类把结论词放在句中的写法会因首字不是「回/不」而落进 H 桶，出现「标签写回避、底色却是持有」的矛盾（2026-10-09 荣昌生物实测）。⚠️ **第二步只能搜首词，不能扩到全串**，否则「HOLD（不新增 / 逢高减持）」会被括号里的「减持」误判为 S，「中性偏空 · 观望（回避追高）」会被误判为 N。

## 台账页内「刷新现价」（2026-10-23 新增，`render_watchlist.py`）

台账页头下方有 `#pxbar`：`↻ 刷新现价` 按钮 + 行情时点 + 「交易时段每 60s 自动刷新」勾选（localStorage 键 `wl-pxauto`）。

- **取价通道**：腾讯 `https://qt.gtimg.cn/q=<secid>,<secid>…` 返回 `v_<secid>="1~名称~代码~现价~…"` 形式的 **JS 赋值**，用 `<script>` 动态注入即执行，**天然绕过 CORS**（fetch 会被挡，对方不返 ACAO）。实测四板块前缀全通：沪 `sh` / 深 `sz` / 港 `hk`+5位 / 北 `bj`；单批 30 只约 150ms；现价在 `split('~')[3]`、涨跌幅 `[32]`、行情时间 `[30]`。
- 🔴 **正文/注释里禁止出现字面量 `<script>`**（含 `/* … <script> … */`）—— HTML 解析器与门禁的正则都会把它当标签，导致 `<script>` 开闭错位、把整段 JS 判成语法错。要写就写「script 标签」。
- 🔴 **数据模型用 JS 赋值 `var WL_MODEL = {...}`，不要用 `<script type="application/json">`** —— 后者的内容会被 `verify_report.py` 的 `check_js_syntax()` 当 JS 编译而误报语法错。
- 🔴 **刷新必须全量重算，不能只改现价那一格**：顶部 verdict、5 张 KPI 中 2 张、潜在空间分布 7 档、赔率矩阵 12 格 + 行/列合计、分区 chips 的「正空间」数、A 区结语、三键排序、持仓 Tab 的市值/浮盈/仓位占比，全部吃现价。只改一格会让页面自相矛盾（2026-10-12 已踩过一次）。
- **文案单一事实源**：所有分支措辞以模板串形式定义在 `render_watchlist.py` 顶部（`V_T_*` / `Z_T_*` / `SP_T_*` / `MX_T_*`，汇总为 `TPL_BAG`）。Python 首屏用 `.format()` 渲染，**同一份模板串随 `WL_MODEL.tpl` 进页面**，JS 只做数字替换、不持有任何文字 —— 两处措辞不可能漂移。
- **分区归属是快照口径**：刷新只改 `data-pos`（影响 chips 过滤与排序），**不重新分区**（A 区卡片与 BCD 表格是两套 markup，搬移等于重渲）。若有标的跨越 0 线，A 区结语会显式写出「另有 N 只空间已转负 / M 只已转正但仍列在下方分区（同上，需重渲台账重新分区）」，不静默说谎。
- **降级**：任一批失败或超时（9s）→ 保持渲染时快照，页头只更新提示文案，不抛异常、不置空。
