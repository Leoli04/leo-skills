## 一 · 红线速查（58 条）

### 事件 · 传导与催化

1. **宏观利好 ≠ 个股利好。** 先验「事件 → 行业 → 公司利润表」传导链是否贯通；核心是识别身份错配 —— 收租方 / 平台方 / 渠道方 ≠ 交易方，收入由合同锁定、与行业景气脱钩。最有力的反证是「行业数据创新高而公司核心利润下滑」
2. 利好要定时滞；「事件前已有正面报道、事件日仍大跌」= 时序证伪，利好已被定价
3. **β 级利好不能对冲 α 级利空**
4. **已兑现的催化不追**；催化必须 6–12 个月内可见。更远的催化只可用于跟踪，不可作买入理由
5. 政策主题要问落在哪个板块、毛利多少 —— **政策给收入不给利润率**

### 估值与筛选

6. **PB 双视角必做**（近两年 vs 十年 / 全历史），**背离时以十年为准**
7. **低 PE 必须先验「分母能不能持续」** —— 盈利在顶时 PE 低是假象
8. **峰值利润 PE 是反向指标**；周期顶估值锚 = 上轮周期顶市场给的倍数，峰值盈利越确定应给倍数越低
9. 判断贵贱**三维同看**：年内涨幅 + PE/PB 分位 + 同业横向。「跌了一半」不是买入理由，「板块内最便宜」是相对陷阱
10. **筛选标准全流程一致**：换标准须显式说明并重排；剔除理由禁用「超目标价 / 已分析过」，须用估值分位或商业模式重述。候选池独立于覆盖进度
11. **跨年度目标价必须折现 + 概率加权**，折现因子 1/(1+WACC)^n
12. **终值威胁分层采纳**：不进当期 EPS，但封顶退出倍数

### 周期与位置

13. **周期股「PE 低」是卖出信号，不是买入信号**；「PE 高 / 为负 + PB 分位低」才是周期反转候选，但仍须先过供给要素
14. **周期定位五要素（价格 / 供给 / 需求 / 库存 / 成本曲线）缺一不可**；供给端不配合时，价格反弹一律按假复苏处理 —— 价格反弹 ≠ 产能出清
15. **周期与结构必须分开归因**：价差驱动 = 周期修复（假反差，须剔出前奏候选）；判据是「价差回落时利润还在不在」
16. **「剔除周期行业」只作用于第 9 步前奏态扫描**，不适用于已覆盖周期标的的分析，也不等于「周期股不可买」
17. 周期股横向比较用**单位产能指标**（头均市值 / 吨产能市值 / 桶油市值 / 单箱运力市值），绝对市值与绝对 PE 不可比，且须与 PB 分位同看
18. **周期股卖在景气**：估值到位 / 供给重启（在建工程回升、新产能公告密集）/ 商品价进 80% 分位以上 / 单位盈利连续两季转弱；**禁用季报利润判断周期拐点**（季报是滞后确认）

### 环境 · 大势与技术

19. **宏观变量没有普适符号** —— 同一变量对不同行业符号相反；使用前必须分流分子 / 分母，并给出强度与时滞。「利率升 → 股价跌」这类单链等于没分析
20. **无法落到利润表的宏观判断，不得作为买入理由**；传导结论须落到可跟踪指标（财务费用率 / 汇兑损益占利润比 / 出口收入占比…）
21. **大势只调仓位，不替代个股尽调** —— 不得因「大盘要涨」买入未过尺子的标的
22. **技术分析只服务择时与风控**（买点区域、止损位、R/R 分子）；不得用于选股或估值，不得由「跌破支撑」反推基本面变坏
23. **行业景气必须定位到档（+2~−2），且每一档须挂可查先行指标**。说不出来一律判 0（平稳），不得凭印象给 +1/+2；档位只描述**当前已发生的事实**，不预测未来路径。**景气判断不得直接等同于买入理由** —— 它只调整情景概率，不改变估值分位这个主锚

### 盈利质量

24. **高增长必做「半年环比 + 单季环比」双重拆解**；季节性证伪用同一年度 Q2→Q3 环比
25. **净利率 < 8% 必做毛利率敏感性 + 汇兑敞口**（毛利率降 1pct → 利润降约 14%）
26. **经营现金流由正转负是质量硬伤**，须与季节性拆开
27. **一次性收入单独剔出**，问「剔掉后主营增速还剩多少」；**高基数的下一季是增速陷阱**
28. **利润成色好 ≠ 经营未恶化**：扣非占比高 + 扣非增速低同时成立时，「成色好」恰说明经营性利润本身停滞
29. **研发刚性陷阱**：研发 ≈ 毛利额时，订单恢复也换不来利润弹性

### 筹码与交易

30. **减持价只证明「减持价偏贵」，不证明「现价便宜」**，不可反推买点。减持从来不是买入信号
31. **筹码四件套同看**；**股东户数下降 ≠ 筹码集中**（须查年报「披露日前一个月末」户数）
32. **被动 ETF 增减持 = 指数编制与申赎**，不构成主动看多
33. **R/R 分子禁用「合理价值上沿」**（循环论证），取「最近有效阻力 ÷ 止损位」
34. **止损位 ≠ 保证成交价**；**以仓位为第一风控**，单一标的组合冲击 ≤ 1.5%
35. **同等期望回报下，永远选「可跟踪的风险」** —— 连续型下行优于二元型下行
36. **利好消息密度峰值 + 股价滞涨 = 派发特征**；筹码判断必须落到可查数据（基金家数 / 股东户数 / 北向 / 龙虎榜），**禁用「庄家吸筹 / 主力洗盘」等不可验证叙事**

### 跨境与口径

37. **A/H 溢价按部分收敛 haircut −20% ~ −25% 计入目标价**；H 股 IPO 价是发行折价 / 清算价 ≠ 内在价值；H 股递表本身即压制 A 股估值中枢，不必等发行
38. **港股必做汇率校验**：财报双口径倒推汇率，归母 × 汇率 ≈ 接口值
39. **关键数字必须标来源 + 时点 + 口径**；口径不可比时禁用比率（见 `methodology.md` §02 的 10 条口径陷阱）

### 前奏识别

40. **市值倍数 ÷ 利润倍数 > 1 是赚估值的钱**（叙事定价，安全边际框架不适用），< 1 才是赚利润的钱
41. **必须框架驱动扫描，不能新闻驱动**；「报表反差」须分辨真假（结构改善 vs 周期修复）；已排除方向与「出海 ≠ 前奏」见第 9 步

### 持仓与交付纪律

42. **买入成本是心理锚，市场不认。** 不以「回本」为决策依据。成本价本身不产生支撑 —— 产生支撑的是全体持有者的成本分布
43. **初筛结论必须显式声明「深度不足」**，不得与深度覆盖结论并列
44. **无验证点不出结论；验证点未通过不加仓**
45. **报告是给投资者的，不是给方法论执行者的** —— 方法论对分析的约束（步骤号 / 「合法尺子·禁用尺子」/ 判据术语 / 内部文件引用）不得原样写进报告正文，须翻译成读者能懂的业务语言。**禁用**引用读者拿不到的 `references/*.md`，禁用「红线 / 陷阱 / Phase / 流水线」这类内部计数与工序词。**执行方式**：交付前必跑 Phase 9.5 第二遍第 9 条（读者视角通读五动作 —— 导出渲染文本 → 扫内部工序词 → 扫自证性文字 → 逐节问「对投资者有什么用」→ 结论页单独重读）。**判否标准**：扫出任意一个内部工序词或自证性文字即为未通过
46. **卖方目标价不得以「未折现名义价」出现在显眼位置** —— 卖方目标价是报告里最容易制造「便宜感」的数字，把「均值 X 元 / 较现价 +YY%」放进顶部指标卡属结构性误导（非数据错误）。引用时必须：① 同时显示折现后可比价 ② 列出至少 2 个平台的读数并说明本报告取的是哪一版 ③ 与自身三情景折现价并排对照 ④ 检查卖方近期是上调还是下调预测。**若卖方自己的盈利预测与你的中性情景接近，必须点明分歧在 PE 倍数而非盈利预测** —— 这才是真分歧。评级与目标价应读作「卖方立场声明」，不是价格预测
47. **看多方向的定性断言必须挂数据，否则删除** —— 「租金水平仍显著低于市场价」「品牌溢价能力强」「护城河极深」这类**无对比基准的定性断言**，会单方面抬高读者的价值感，且无法被证伪。凡属看多方向（支撑「值这个价」）的定性表述，要么给出可查数据与对比基准，要么删除。**看空方向的定性表述同样处理** —— 双向适用，标准一致。**自检方法**：把每个形容词问一遍「和什么比？数据在哪？」
48. **正文中所有绝对数值必须全篇唯一、自洽，且舍入风格统一** —— ① **唯一性**：同一指标在报告不同位置出现两个不同数字即为 FAIL（如仓位上限一处写「≤0.5%」、另一处写「≤5%」）。② **舍入风格统一**：全篇同一指标的舍入方式必须一致 —— 本例中性折现价 `10.567`，旧文按**截断**写 `10.56`、新增的两张表按**进位**写 `10.57`，同一份报告出现两套舍入；同类事故还有 `−4.96%` 与 `−4.97%` 并存（源自 `−4.9657%` 的两种舍入）。**新增段落 / 表格最容易带进第二套舍入**，写完须把该指标全篇 grep 一遍对齐。③ **派生值须与源数据表勾稽**：拆解式里的**每个被减数 / 除数**都要与它引用的那张数据表逐一对上 —— 本例环比拆解写「46.93 → 56.89 亿」算出 +21.2%，而同表单季营收实为 **45.93**（45.93 → 56.89 ＝ +23.9%，才与标注的 +23.9% 自洽）；笔误的被减数会让拆解式与结论值打架。④ **自算列必须整列复算，并校验「同一列各行是否用了同一个分母」** —— 占比 / 增速 / 差值这类**由报告自行计算的列**，比引用来的外部数据更易错（引用有出处可核，自算没有）。**最隐蔽的错误不是算错一个数，而是同一列不同行悄悄换了分母** —— 本例「占比 2023→2025」列：2023 年「主营 = 总营收 = 112.81」两基数相等，2025 年「主营 192.61 ≠ 总营收 197.07（差 4.46 亿其他业务收入）」，原表 2025 各行用了总营收基数、2023 各行用了主营基数，导致 2025 占比被系统性低估 0.1–1.2pct（26.7 应为 27.3、50.7 应为 51.8、6.6 应为 6.8、9.9 应为 10.1）。**根因是「基数在基准年恰好相等，掩盖了它的存在」**。**执行方式**：对每个自算列，先明确写出该列的分母是什么，再把当前行的分子 ÷ 分母复算一遍；若某年的两个候选分母（如主营 vs 总营收）数值相等，须在表下明写「该列分母取 XX 口径」，否则后续年份一旦出现差额，错误无法察觉。**同一列不得混用两种分母。** ⑤ **列标题即口径契约**：若列标题写「占比 2023→2025」，则该列只能填 2023→2025 的口径，不得填 2024→2025 的增速（真实事故：贸易服务行填入 `+138%`，实为 2024→2025 营收增幅 138.6%，而 2023→2025 应为 +178%）；同一单元格混两个时间口径属隐性错误，读者极难察觉。**这些数字不在 verify_report.py 的自动检查范围内，必须人工整列复算**
49. **PE 的口径必须反算验证后才能标注** —— 行情软件同一时点会并列给出动态 / 静态 / 另一口径三个 PE，对应净利基数完全不同（本例：动态 13.53 / 静态 15.35 / 另一 14.45，隐含净利 44.91 / 39.58 / 42.05 亿）。**标注方法**：市值 ÷ PE = 隐含净利，与哪个口径的利润对得上就叫哪个。**⚠ 行情软件的字段命名可能与惯例相反** —— 本例腾讯行情把 `14.45x`（隐含 2025 年报归母 42.04 亿）之外的字段标为「静态」，而惯例上 14.45x 才是静态 PE；遇到字段名与反算结果不符时，**以反算结果为准，并在报告里点明「行情软件字段命名与惯例相反」**，不要照抄字段名。**反算对不上任何口径时，注明「口径未注明」并说明疑为哪种口径，仅列示不采用**（本例 15.35x 隐含 39.58 亿，与 42.04 归母不符，疑为扣非）。**若采用动态口径，必须额外说明其是否含一次性项目** —— 动态 PE 的隐含利润含大额一次性结转时，不得据此得出「历史最低分位 → 便宜」，因为同一份报告别处正在论证该利润不可持续，两段会互相拆台。**分位（相对位置）与绝对倍数分属不同口径体系，不可并列比较** —— 分位可用，倍数不可
50. **跨节数据的一致性三查** —— ① **口径一致性**：同一指标在不同节的对比基准（同比 / 环比）必须分别标注，防「一个项目贡献两笔增量」的误读。② **加总一致性**：任何分部 / 分项表，加总须等于并表总额；差额须单列并**写对差额的符号方向** —— 差额为正（加总 < 并表）是「未分配的其他业务收入」，差额为负（加总 > 并表）才是「内部抵销」，两者不可混用同一标签（真实事故：差额 +1.99 亿却标为「其他 / 内部抵消」）。未披露时注明「未单独披露」。③ **假设一致性**：情景假设隐含的增长率若与报告别处的趋势论断冲突（如中性情景隐含 14% CAGR，而正文论证经常性增速已停滞），必须正面拆解该情景由哪几块拼出，不能留缝。**这三查不在自动脚本范围内，属交付前人工必做**
51. **零编造原则覆盖到图表的每一个坐标点，不只是数据集** —— 图表的「真实感」由点位/参考线/分区锚点共同构成，读者无从分辨哪些点有数据、哪些是画出来占位的。因此：① 每张多序列图的**每一个点**要么来自实测数据、要么在图例或图注中显式标注「示意」；② **参考点、分区锚点、阈值线**若只是「标明方位」而非实测值，图例名须带「示意」二字（如「买入区（示意，无量化口径）」）；③ 图注须**指名道姓地说明哪几个点是实测、哪几个是示意**，不得用「均为真实点位」这类笼统自证；④ 若某张图（如四象限同业对比）除本公司外**其余点位都拿不到实测数据**，则该图不成立，须删图或降维为只画本公司单点的图。**判否标准**：图注声称「真实」而数据集中存在无来源点位即为 FAIL
52. **HTML 用到的 CSS 类必须在 `<style>` 中有定义** —— 类名不匹配是**静默失败**：元素照常出现在 DOM 与渲染文本里，但丢掉了全部样式（无边框、无底色、进度条 `height:0` 不显示），浏览器里表现为「一堆裸文字」，而源码检查、`div` 配平、文本回查**全都抓不到**。典型成因：报告的卡片结构升级了（如财务健康卡从「标题+数值」改成「标题+进度条+注释」），HTML 换了新类名，`<style>` 却还留着模板的旧类名。**执行方式**：交付前跑 `verify_report.py` 的「CSS 类完整性」项（用到但未定义的类一律 FAIL）；改过卡片结构后，另在浏览器里量一次目标元素的 `getComputedStyle`（`height`/`background`/`border` 是否非零）。**豁免**：靠内联 `style` 表达或纯语义占位的类（如 `.footer`）可登记在脚本的 `CSS_UNDEF_OK` 白名单里
53. **比率类指标必须写明分母基准** —— 「摊薄比例 X%」「稀释 Y%」这类比率，**分子分母取哪个基数，含混时会引起 1~2 个百分点的误读**。真实事故：H 股摊薄写「摊薄比例 10%」——它是「新股 6.09 亿股 ÷ 发行后总股本 60.93 亿股」（＝原股东权益摊薄 −10.00%），但读者极易读成「股本增加 10%」（实际 6.09 ÷ 54.84 ＝ +11.11%）。**写法**：把分子分母都写出来（如「新股占发行后总股本 10%，即原股东权益摊薄 −10.00%；换算成对发行前股本的增幅为 +11.11%」），并在表下补一行推导式。**同类**：占「发行前」还是「发行后」、占「总资产」还是「股票仓位」、增「同比」还是「环比」—— 凡比率必标基准
54. **自检清单里写的维度，正文必须真的有** —— 自检说「营收结构已看近 3 个完整年度 + 最近 4 个季度」，正文却只有单期数据，属**自检虚报**。自检清单是交付质量声明，虚报比缺数据更严重：它会让读的人以为已核过，从而关掉这一维度的警惕。**执行方式**：写自检项时，对每个「已看 N 年 / 已对比 M 家」的断言，在正文里回指到具体表格或图（如「见 ① 节分部三年趋势表」）；回指不到就删掉该断言或补上数据。**同类**：自检说「已对比 4 家同业」，正文只列 2 家；自检说「已算 WACC 敏感性」，正文只有单一 WACC。**判否标准**：自检项里出现无法在正文定位的量化维度即为 FAIL
55. **涉及「商户 / 客户 / 用户侧」的经营指标，必须给出可交叉验证的第三方口径数据** —— 收租型、平台型生意的核心风险都在**下游经营体的健康度**上，而公司自己的表述（「出租率超 98%」「3–5% 年涨租」）是**口径可控的自我陈述**，不能单独作为论证依据。**写法**：① 引用第三方可核验来源（信用评级报告、招股书、行业协会、审计口径），与公司口径并列；② 公司口径与第三方口径覆盖范围不同时**必须写明差异**（本例「出租率超 98%」只对国际商贸城一至五区成立，含生产资料市场 76.13%、宾王市场 36.97% 的全口径加权仅约 90.6%）；③ 给出**多年序列而非单期**，以判断趋势方向。**判否标准**：全文对商户侧经营（续租率 / 租金单价 / 出租率 / 商户数）零量化数据，或只有公司单方口径的整数式表述
56. **自称「必须分部看、禁用并表 PE」，就必须用分部口径算出目标市值** —— 口径声明与估值算式在报告里相隔数千字，最易出现「前面宣称分部、后面用并表归母 × 单一 PE 定目标价」的自我矛盾，且脚本抓不到。**执行方式**：若 Phase 1 判定某公司「禁用并表 PE」（典型：低毛利贸易业务拉低并表质量），则估值节必须并列一张分部估值表 —— 逐业务线「归母化利润 × 该业务的合理倍数」求和，再与并表口径的目标市值并排比较，最后回答**「换分部口径结论变强还是变弱」**。**三条纪律**：① **一次性项目绝不给经常性倍数**（房产结转类给 0–5x，不得按收租业务给 15x+）；② 必须写清本表**不含成长溢价**，是「静态验算」而非「目标价锚」；③ 分部的利润要**归母化**（乘归母占比），不能用并表分部利润直接乘倍数
57. **同一标的留有旧版报告时，新版必须做复盘对照** —— 三种情形分别处理：**① 结论相反** —— 逐项点名推翻的是哪个数（估值读数 / 目标价 / 关键经营指标 / 重大事件状态），并附「两版为什么差这么多」的归因；**② 结论相同** —— 写「延续」并说明新增了什么证据使其更确定；**③ 旧版有事实错误** —— 明写「前版此处有误」并纠正（本例：H 股「已完成」实为「已递交申请」、PE 分位 57% vs 0.14% 口径反差），**不得沉默覆盖**。复盘段硬要求：**旧值 / 新值 / 差异原因三列齐**，不得只写「已更新」。无旧版则不写，但交付说明须提一句「工作区未发现同标的旧版报告」
58. **看多逻辑的第一支柱若含「高股息率」，必须做股息可持续性测算** —— 股息率是「便宜感」最直接的来源，但「高分红的钱从哪来」被跳过的报告等于没收尾。**执行方式**：列出**近 12 个月实际派息总额 → 与当年 OCF 对比（OCF 能否覆盖）→ 与账面货币资金对比（现金能付几年）**，并回指分红率与 OCF 是否转负。**判否标准**：① 分子用「每股派息 × 总股本」但分母用「归母净利」时未说明口径；② 只写「股息率 X%、分红率 Y%」而不回答「现金够不够」；③ 若分红金额主要由**融资性现金**（如 H 股募资）支撑，必须点明「股息来源的性质变了」，不得与经营性现金流分红的性质混同

## 二 · 陷阱对照（45 个）

| 陷阱 | 正解 |
|---|---|
| 把「跌了一半」当买入理由 | 参照系是公司自己的历史估值分位，不是跌幅 |
| 用近两年 PB 分位判低估 | 必须同时看十年 / 全历史分位（近两年中枢可能被主题行情抬高） |
| 把股东户数下降读作「筹码集中」 | 查年报「披露日前一个月末」户数，识别主题期涌入的散户余量 |
| 用产业资本减持价反推买点 | 减持价只证明「该价偏贵」，不证明「现价便宜」 |
| 引用卖方远期 PE 目标价 | 必须折现；净利率为负的公司给 50x+ PE 本身不成立 |
| **把卖方目标价的「较现价 +XX%」直接当上涨空间** | 卖方目标价未折现，且常是多个平台里的最高值。必须过三面检验：折现后可比价 / 多平台口径交叉 / 与自身情景对照。折现后往往只剩 +13%~27% |
| **只看卖方目标价、不看卖方动向** | 若券商在下调盈利预测的同时维持「强推/增持」且目标价下移，评级已滞后于其自身模型；报告若用「过去 12 个月均值」就滞后于这轮下调 |
| 用 PE 给亏损公司估值 | 只看 PB 分位，并注意净资产缩水导致的「被动高估」 |
| 把 ETF 增持当主动看多 | 被动资金反映指数编制与申赎 |
| 忽略研发刚性 | 研发 ≈ 毛利额时，订单恢复也换不来利润弹性 |
| 用毛利率抬升直接推利润改善 | 先过 G2b 四项条件（含营收同比不为负、绝对毛利额同比为正） |
| 把买入成本当价值锚 | 成本不影响期望价；「回本」不是持有理由，用「期望价 ÷ 现价」重判 |
| 追已兑现的催化 | 要「催化未兑现」；题材落地后连板 / 政策落地后放量均属兑现完成 |
| 用「行业数据创新高」推个股利好 | 先验身份是否错配（收租方 / 渠道方收入由合同锁定，与行业景气脱钩） |
| 把初筛结论当深度结论 | 无完整覆盖必须显式声明「初筛，深度不足」，且不得作为加仓依据 |
| 忽略流动性下限与组合容量 | 自由流通过小则进出成本高、过大则无法被资金定价；须写明用的是哪一侧约束 |
| 用低 PE 选周期股 | 周期顶 PE 最低。改看 PB 分位 + 「上轮周期顶倍数 × 峰值盈利」再折现 |
| 把价格反弹当周期反转 | 先验供给是否出清（在建工程 ÷ 固定资产、开工率、库存天数）；供给不出清，一律按假复苏处理 |
| 用当期年化盈利给周期股估值 | 用中周期均价做正常化盈利再折现；底部、顶部、下行三段均禁用 PE |
| 把「剔除周期行业」误读为「周期股不可买」 | 该规则只作用于第 9 步前奏扫描，防价格修复型利润跳升污染 G1 / G2b |
| 「营业收入增加 → 股价上涨」/「盈利增加 → 股价自然上涨」 | 线性外推。须做单季环比双拆解、剔一次性、验扣非成色，并警惕高基数的下一季是增速陷阱 |
| 「利率上升 → 股价下跌」单链 | 未分流分子 / 分母、未给强度与时滞；同一变量对不同行业符号相反 |
| 由「跌破支撑线」反推基本面变坏 | 技术面只服务择时与风控；基本面变坏须由报表与传导链证明 |
| 「有主力吸筹 / 庄家在洗盘」 | 不可验证叙事。筹码判断须落到基金家数 / 股东户数 / 北向 / 龙虎榜 |
| 「公司回购 = 利好」 | 须查注销 vs 库存股、资金来源（自由现金 vs 借款）、回购价所处估值分位 |
| 「利好消息密集 → 买入」 | 信息密度峰值常是派发窗口；须看股价是否滞涨 + 筹码是否迁移（基金家数 / 户数） |
| 只看期望价、不算胜率 | 期望价可由「低概率 + 极端情景」单方面撑起。须同时给出胜率（情景价 ≥ 现价 × 1.15 的概率之和）与三档判定；胜率 < 30% 与期望价不达标**各自独立否决** |
| 用「机构一致预期偏乐观」代替胜率数字 | 定性表述不是测算。三情景价格、概率、概率之和 100% 必须显式列出 |
| 只做行业横向、不定位行业景气 | 同业一起涨可能是行业景气上行，也可能只是集体反弹后一起回落。须纵向定五档（+2~−2）并喂给情景概率 |
| 「行业不错 → 调高乐观概率」 | 无先行指标的景气判断无效。每一档必须挂可查指标（价格分位 / 产能利用率 / 库存天数 / 同业营收同比），说不出来一律判 0 |
| 把行情软件的**动态 PE** 标成 TTM / 扣非 | 同一时点行情软件常并列给出动态 / 静态 / 另一口径三个 PE，三者对应的净利基数完全不同。**标口径前必须反算验证**：市值 ÷ PE = 隐含净利，与哪个口径的净利润对得上就叫哪个。**动态 PE 含当期一次性项目时，不得据此得出「极低分位 → 便宜」** —— 一次性项目撑起来的高利润会压低 PE，与「该利润不可持续」的论断互相拆台。**分位可用于相对位置，绝对倍数不可跨口径并列比较** |
| 把同一笔一次性收入同时算作「同比增量」与「环比驱动」 | 同一收入项在不同对比基准（同比 vs 环比）下会各出现一次，读者易误读为「一个项目贡献了两笔增量」。两处必须分别标注口径（同比 / 环比），并说明是同一收入项的两种呈现 |
| 分部营收加总 ≠ 并表总营收而不作说明 | 分部表按业务线列示，通常不含「其他 / 内部抵消」项。加总后与并表总额的差额必须单列一行或显式注明「未单独披露、不作估算」，否则读者自行加总会对不上，进而怀疑全表数据 |
| 情景假设的隐含增速与自身风险论述打架 | 若中性 / 乐观情景隐含的 CAGR 明显高于报告别处论证的「经常性增速已停滞」，必须**正面拆解该情景由哪几块拼出**（经常性增长 + 已签约项目结转 + 新业务减亏），并说明不依赖经常性利润加速。否则情景假设与风险论述之间存在未弥合的缝 |
| 新增表格带入第二套舍入 | 同一指标在旧文按截断写、新增表格按进位写（如 `10.567` 既写成 `10.56` 又写成 `10.57`；`−4.9657%` 既写 `−4.96%` 又写 `−4.97%`），同一份报告出现两套舍入风格。**新增段落 / 表格最易带入** —— 写完须把该指标全篇 grep 对齐到同一套舍入 |
| 拆解式里的被减数写错（与源表不符） | 拆解式 / 推导式引用的数字必须与源数据表逐一对上。真实事故：环比拆解写「46.93 → 56.89 亿」算出 +21.2%，而同表单季营收实为 45.93（45.93 → 56.89 ＝ +23.9%，才与标注的 +23.9% 自洽）—— 笔误的被减数使拆解式与结论值直接打架 |
| 照抄行情软件的 PE 字段名 | 行情软件的字段命名可能与惯例相反：本例腾讯行情把 14.45x（隐含 2025 年报归母 42.04 亿，才是通常意义的静态 PE）之外的字段标为「静态」。**以反算结果为准**，字段名与反算不符时在报告里点明「行情软件字段命名与惯例相反」；反算对不上任何口径时注明「口径未注明，疑为 XX，仅列示不采用」 |
| 自检项写了维度、正文却没有 | 自检清单说「营收结构已看近 3 个完整年度」，正文只有单期数据；说「已对比 4 家同业」正文只列 2 家。**自检是质量声明，虚报比缺数据更严重** —— 读的人会以为已核过而关掉该维度的警惕。写断言时须回指到具体表格 / 图，回指不到就补数据或删断言 |
| 收租 / 平台型生意缺商户侧量化数据 | 公司自己的「出租率超 98%」「3–5% 年涨租」是**口径可控的自我陈述**，不能单独作为论证依据。全文对续租率 / 租金单价 / 出租率 / 商户数零第三方数据 = 最大证据空洞。**须引第三方可核验来源（信用评级报告 / 招股书 / 协会）并给多年序列**，公司口径与第三方口径覆盖范围不同时必须写明差异 |
| 把「公司口径的覆盖率」当作「全口径事实」 | 「出租率超 98%」在本例只对国际商贸城一至五区成立，全口径（含生产资料市场 76.13%、宾王市场 36.97%、数贸中心 73.09%）加权仅约 90.6%。**用一个子集的口径概括全部资产，是把最好的部分当成整体** —— 凡覆盖率 / 出租率 / 利用率类表述，都要先确认统计范围是否等于资产全集 |
| 标题声明的条目数与表内实际条目数不符 | 本文件真实事故：陷阱表标题写「40 个」而表内只有 39 行、自检标题写「61 项」而清单只有 59 条。**计数虚报是最隐蔽的一类自检失效** —— 读者看到「已核 61 项」会直接关掉警惕，实际少核的部分无人发现。**执行方式**：每次增删条目后，用脚本回数（`grep -c` 或 `verify_report.py`），不靠记忆填标题；报告的清单标题数、模板标题数、redlines.md 标题数、来源行「故为 X / Y / Z」四处必须与各自文件内的实际条目数逐一相等 |
| 宣称「禁用并表 PE」却用并表口径定目标价 | 报告前段判定「必须分部看」，后段目标市值却用「并表归母 × 单一 PE」 —— 口径声明与算式相隔数千字，读者不易察觉。**宣称分部就必须列分部估值表**（逐业务线归母化利润 × 该业务合理倍数求和），并与并表口径并排比较、回答「换口径后结论变强还是变弱」。**另注意**：分部表里的一次性项目（房产结转）不得给经常性倍数，且须写明本表不含成长 |
| 高分红的钱从哪来没算 | 股息率是「便宜感」最直接的来源，但只写「股息率 X%、分红率 Y%」而不回答「现金够不够」，等于没做估值闭环。**必须算**：近 12 个月派息总额 vs OCF（能否覆盖）vs 货币资金余额（够付几年）。**若分红实际由融资性现金（H 股募资）支撑，须点明分红来源性质已变** |
| 自算列同一列各行换了分母 | 「占比 / 增速」这类**自算列**最隐蔽的错误不是算错一个数，而是**同一列不同行悄悄用了不同分母**。真实事故：「占比 2023→2025」列 2023 行用主营业务收入（112.81）、2025 行用营业总收入（197.07），两基数在 2023 年恰好相等、2025 年差 4.46 亿，导致 2025 各行占比被系统性低估 0.1–1.2pct（26.7/50.7/6.6/9.9 应为 27.3/51.8/6.8/10.1）。**基准年两基数相等 = 掩盖错误的温床**。须整列复算 + 表下明写分母口径 |
| 列标题口径与单元格内容不符 | 列标题写「占比 2023→2025」，单元格却填 2024→2025 的增速（贸易服务行填 `+138%`，实为 2024→2025 营收增幅 138.6%，2023→2025 应为 +178%）。**同一单元格混两个时间口径属隐性错误**，读者难以察觉。列标题即口径契约，填数前先对齐 |
