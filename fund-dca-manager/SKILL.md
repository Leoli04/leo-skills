# 基金定投仓位管理

## 与 fund-etf-review 的分工

| | fund-etf-review | 本 skill |
|---|---|---|
| 回答的问题 | **买什么** | **怎么买、买多少、何时卖** |
| 核心动作 | 审、比、出研报 | 算、分配、执行 |
| 典型触发 | 「评估这只基金」「有没有更便宜的替代品」 | 「本周投多少」「三只都在跌先买哪只」 |
| 输出物 | HTML 研报 + 资料库 | 终端执行表 |

两个 skill 是先后关系不是替代关系：先用 review 选定标的，再用本 skill 执行。**不要在本 skill 里做选品评估，也不要在 review 里做仓位分配。**

## 三条核心原则

**1. 统一量纲用估值历史分位，不用 PE 绝对值。**
创业板 PE 30 和沪深300 PE 13 不能比较，因为盈利结构不同。跨标的唯一可比的是「该指数 PE 在自己历史中的位置」。分位窗口必须披露（蛋卷口径自 2016-07 起，约 10.3 年，不含 2015 泡沫）。

**2. 单只决定「该不该加」，账户决定「能不能加」。**
这是本 skill 与普通定投的分水岭。每只基金按分位算出「理论投入额」，但账户预算不够时，按分位从低到高分配——**最贵的先砍，不是平均分，也不是谁跌得狠买谁**。

**3. 每只基金设资金池 + 该档天花板。**
防单只在低位把钱提前投光。天花板 = 资金池 × 该档 cap_ratio，累计投入达到即停手，等估值下移到更高天花板那一档再恢复。

## 工作流

### Step 1 读配置，缺项先补齐

配置在 `dca_plan.json`（模板见 `scripts/dca_plan.example.json`）。必填项：

- `accounts[]`：每个账户的 `id` / `total_capital` / `weekly_budget_base` / `weekly_budget_cap`
- `funds[]`：`code` / `name` / `account` / `index_code` / `pool` / `base_weekly` / `invested` / `shares`

用户没给齐时**先问再算**，不要猜金额。缺 `index_code` 时查 `_可用指数代码` 对照表；表里没有的指数，改用手工填分位的降级路径。

### Step 2 跑脚本出表

```bash
python dca_weekly.py                 # 默认读同目录 dca_plan.json
python dca_weekly.py --config x.json
```

脚本自动：查蛋卷估值 → 落档 → 算理论额 → 检查天花板 → 按账户分配预算 → 输出分组表 → 检测重复暴露 → 落盘。

## 结果落盘

每次运行自动写两处（`--no-save` 可关闭，只看不存）：

| 产物 | 位置 | 用途 |
|---|---|---|
| 快照 | `定投记录/YYYY-MM-DD.md` | 当日完整表 + 本周执行清单，可直接粘贴归档 |
| 台账 | `定投记录/ledger.csv` | 追加写入，**累计投入的事实源** |

台账机制：

- **按 ISO 周去重**（`iso_week` 列）。同一周内周一跑、周三再跑，不会重复记账，第二次只显示「本周已执行 X，本次不重复」。
- `actual` 列 = 实际投入，可手工修改。计划投 250 但实际只投 200 时，改这一列。
- 下次运行读 `actual` 累加；配置里的 `invested` **只填启用脚本之前的历史持仓，之后不要再改**，否则会重复计算。
- `cumulative` 列记录每次投后的累计投入，供对账。

### Step 3 逐项复核脚本结论（不可跳过）
- **分位是否最新**：看输出首行「数据日」。蛋卷通常 T+1，若用户问的是当日，需说明滞后一天。
- **重复暴露告警**：同一 index_code 被多只基金跟踪 = 同一风险押两次，必须提示用户合并或调权重。
- **天花板告警**：出现「已达该档天花板」说明该只已投满本档额度，不是故障。
- **预算不足告警**：被砍掉的标的下周可能排回前面，不是「不买」。

### Step 4 给加减仓结论（不只是念表）

按 `references/tier_rules.md` 的档位系数表解释「本周为什么是这么多」，并明确下一步触发条件：跌到哪个分位该加档、涨到哪个分位该减档。**只说金额不说触发条件等于没给结论。**

### Step 5 止盈检查（有持仓盈利时必做）

按 `references/exit_rules.md` 检查四层触发：L1 停投线、L2 移动止盈、L3 估值极值、L4 时间复核。有任一层触发或接近触发，必须主动提示，不要等用户问。

### Step 6 渲染台账并发布（用户要「看得见」时）

```bash
python publish_dca.py                # 渲染 + 上传/覆盖资料库
python publish_dca.py --no-upload    # 只渲染本地
```

产物：`定投台账_<记录日>.html`，单文件零依赖，七节结构 = KPI → 本周执行（分账户）→ 估值分位标尺（含档位对照表、代理指数说明）→ 持仓与资金池使用 → 累计投入曲线 → 告警 → 历史记录。

**档位必须在页面上自解释**。只有徽标（S/A+/A/B/C/D/E）没有换算式，读者无法复核金额，也不知道阈值能不能改。02 节固定包含：

| 要素 | 内容 |
|---|---|
| 档位对照表 | 档 / 分位区间 / 系数 / 资金池上限 / 动作 / 本周落此档（列出实际基金） |
| 生成方式 | 由 `tier_rules` 现场生成，**禁止在模板里写死行** —— 改阈值后表与金额必须一起变 |
| 必须声明的三条 | `-` = 无分位数据（是「不知道」不是「不该买」）；D/E 停投 ≠ 清仓；同一徽标可能对应两段系数（`A+` 3–6% 用 3×、6–10% 用 2×），同档两只可差一倍 |
| 金额可比性 | 周投额 = `base_weekly` × 系数，各基金 `base_weekly` 不同，**同为 B 档的两只绝对金额不可比** |
| 终端同步 | `dca_weekly.py` 在合计行下方打印档位图例，终端结论不能只有「档」列没有定义 |

分位口径必须写「2016-07 以来分位」，禁写「历史分位」（蛋卷窗口不含 2015 年泡沫）。

发布规则：
- 首次上传用 `--parent-id ujlYAui5OmAlkvfEjReBOW`（资料库「投资 / 基金和ETF」），成功后脚本自动把 `node_block_id` 回写进 `dca_plan.json` 的 `library` 段
- 之后每次运行自动用 `--node-block-id` **原地覆盖**，节点 URL 与标题不变、不产生重复条目
- 覆盖时**不要传 `--file-name`**（会改变节点标题）
- 资料库不支持删除节点，新建前必须确认 `library.node_block_id` 是否已存在

图表口径：
- 分位标尺：绿 ≤22% / 黄 22–47% / 红 >47%，与档位表的偏低/中性/停投线一一对应
- 累计曲线：起点 = 各基金 `invested` 之和（启用台账前的历史持仓），之后按每周 `actual` 累加；y 轴上界取 nice number
- 「使用率」条的红色阈值 85%，超过即触发「逼近天花板」告警

## 输出格式

1. 一句话结论：本周各账户合计投多少，哪只拿到钱、哪只被排后
2. 脚本原始表（保留，便于核对）
3. 逐只说明：为什么是这一档、下一次档位切换的点位
4. 告警汇总：重复暴露 / 天花板 / 停投 / 止盈触发

## 红线

- **不预测收益，不推荐买卖哪只基金。** 本 skill 只做预算分配与纪律执行，选品交给 fund-etf-review。
- **不擅自改用户配置里的金额。** 需要调整 `total_capital` / `base_weekly` 时先说明理由并确认。
- **不用「跌了多少」做加仓依据。** 唯一触发是估值分位；日跌幅只作观察，不作决策变量。
- **不把场外基金当 T 工具。** 场外基金按当日收盘净值成交、<7 天赎回费 1.5%，做 T 在结构上不成立（详见 `references/exit_rules.md` 末节）。
- 数据源只有蛋卷指数估值一个入口时，必须在输出里标注日期与来源；查不到分位的标的明确标 `-` 并说明原因，不要用 PE 绝对值凑数。
