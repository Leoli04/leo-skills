# 笔记模板

起草 `notes/notes.md` 前读取本文件。本模板的目标不是把播客内容尽可能铺满，而是把一集 AI 访谈播客整理成聚焦、可扫读、可复习、能用约 1/4 时间 get 嘉宾观点的学习笔记。

核心原则：**忠实转述，少而准，有抓手。** 读者打开笔记后，应先看到本期核心观点、主题结构和阅读边界，再自己决定是否继续读。不要让 agent 替用户判断“值不值得读”，不要补充对立观点，不要发挥己见，也不要把 chunk 精读结果全搬进正文。

默认整篇笔记主体都是受访嘉宾观点的整理，不要反复写“嘉宾认为”“嘉宾说”“在嘉宾眼里”。只有在以下情况才显式标来源或性质：内容来自 show notes 而不是 transcript、是主持人的观点、是 agent 的基础概念补充、是预测/暴论、是转写存疑或来源不一致。

## 笔记应该长什么样

学习笔记不是分类档案，也不是散文化长文。理想形态是：

- 主题少：正文聚焦 4-6 个大主题，低知识密度内容压缩或舍弃。
- 正文要有两层标题：H2 记主题，中文编号、可检索但不下结论；H3 用判断句，判断必须是嘉宾的，不是 agent 的评语。文档 H1 用「主题 + 核心判断」，不用播客原始标题（原标题下放到元数据）。不写“核心概念”“关键论点”这类标签。
- 段落有抓手：大段 prose 前用加粗小标题或一句话先导，让读者扫一眼知道这一段讲什么。
- 论证讲清楚：只留下结论不够，要保留嘉宾为什么这么判断、限定条件是什么。
- 边界诚实：事实、预测、转写存疑、agent 补充要能分辨，但不要拆成笨重的分类大区。
- 可回溯：关键定义和关键判断尽量挂 transcript 中已有的 `[mm:ss]` 锚点；无时间戳则不编造。

## 推荐结构

```markdown
# <主题：核心判断，例「量化宏观配置：用结构换稳定」>

**元数据**：<节目名>｜<发布日>｜<时长>｜嘉宾 <姓名（身份）>｜主持 <姓名>｜[单集页](<URL>)

## 播客核心内容

<段 1 处境：用当期事实开头，说清这期在解什么困境。不要写“本期节目邀请了……”这类开场白。>

<段 2 答案：一句话主旨——这套做法的本质是什么；再写代价、收益形态与验收口径。这一段是全篇塔尖，必须能统摄后面每一节。>

**<对照表引导，如「五个环节上的取舍」>**

| 环节 | 常见做法 | 他的做法 | 验收口径 |
| --- | --- | --- | --- |
| <不超过 5 行，只留全篇最关键的取舍> | | | |

## 一、<大主题：组织若干小标题>

### <会说话的判断句：嘉宾的判断，不是 agent 的评语>

<开头 1-2 句说明这一节回答什么问题。>

**<小标题或先导句>**：<短段解释。每个自然段尽量只承载一个判断，不要堆成大块。>

**<另一个小标题或先导句>**：<继续解释概念、论证或例子。>

<必要时用列表/表格呈现三层框架、路线对比、优先级、步骤。>

### <小主题二>

...

## 二、<下一个大主题>

...

## <N>、经典 Q&A

<精选 2-4 段最有代表性、例子最生动的问答，保留主持人问 + 嘉宾答的原始对话形态。它放在主体后面作为点缀，不替代前面的主题重组。>

## <N+1>、术语表

<只放真正影响理解的 6-10 个术语。不要写成泛泛词典。>
```

不要默认生成 `## 自测题`、`## 存疑与待核对`、`## 诚实边界声明` 这三个尾部模块。**转写来源与“是否核对过原音频”不写进正文**——那是制作说明，读者要的是内容；溯源写 `source/extraction-notes.md`。存疑信息只在确实影响正文理解时就地提示。


## 成稿规则

Phase 4 产出 `notes/notes.draft.md`，Phase 6 收口成 `notes/notes.md`。本节规则只作用于成稿。

**塔尖**：核心内容节第二段就是塔尖。写完自检——随机抽任意一节，能否挂到它下面。挂不上的节要么删掉，要么塔尖写窄了。

**标题分工**：H2 记主题，读者能拿它检索，不下结论；H3 记判断，可以是嘉宾的观点，不能是 agent 的评语。把标题单独抄出来读，应该像一句结论或一个真问题，而不是目录项。禁用「一页读懂」「一张表」「一条线」「带走点」「两个性质」这类描述文档结构的词。

**核心内容节**：`## 播客核心内容` 独立成 H2，**不编号**，正文仍从「一、」开始。含两段 + 一张不超过 5 行的对照表，3 分钟可走完。不编号的理由是它是概要，不是第 1 个主题。

**体量**：先定档位，再动笔。没有目标值，压缩会停在「看着差不多」的地方。

| 档位 | 汉字量 | 适用 |
| --- | --- | --- |
| 速读 | 3000–4000 | 只留判断链，供事后检索 |
| 标准 | 5000–6500 | 默认；论证保留、细节压缩 |
| 完整 | 8000–10000 | 框架类内容多，需保留推导过程 |

**压缩三刀**：删形容词与程度副词（「非常」「极其」「显著的」多可删而不损信息，它们表达的是强调，不是事实）；删重复（同一判断只留最有力的一处，开头提出又在每节末尾复述是最常见形态）；删铺垫（「在开始之前需要说明的是」「众所周知」删掉读者不会觉得少东西）。

删整块优先于逐句瘦身：逐句改通常只降个位数百分比，还会留下一堆被磨平的论证。删完统计删除率——低于 10% 说明只做了编辑没做删减，高于 30% 说明删到论据了。正常落在 15%–25%。

**术语锚定**：从正文挑 5–8 个核心术语，各定唯一写法，写进 `review/final-review.md`，再全文检索异写，计数必须为 0。三类高发：同音词（风险平价 / 风险评价）、简称全称混用（波动贡献 / 波动性贡献）、译名不统一。放在改字句之前做，否则改完还要再查一遍。

**段落颗粒度**：一段一意，出现「另外」「同时」这类转折就分段；段首句承担导航，应该是主张句，不是铺垫句；单段不超过约 6 行（260 全角字符），超过就拆。连续三段讲同一件事，合并或删掉两段。

**小标题节奏**：同层标题字数大致相当，极差不超过 2 倍；H3 控制在 18 字以内；不连续排三个问句——连排会让文章显得没有答案。

**锚点**：成稿删除全部 `[mm:ss]`，删前另存 `notes/notes.带时间锚点-溯源版.md`。

**不写制作说明**：转写来源、是否核对原音频、本文分几部分、下面这张表、本节带走点——一律不进正文。

## 取舍规则

正文不是 chunk 汇总。合成时先问：**这段内容对目标读者学习 AI/技术知识有没有帮助？**

优先保留：

- 能解释一个 AI/技术概念的内容。
- 受访者给出的框架、判断标准、优先级、路线对比。
- 反直觉但有论证的观点。
- 具体机制、案例、工程做法。
- 对学习者职业判断或产品判断有启发的内容。

压缩或舍弃：

- 开场寒暄、年龄、星座、MBTI、融资、团队规模等低知识密度信息。
- 重复出现但没有新信息的例子。
- 只服务节目气氛的玩笑和口头禅。
- show notes 或页面评论中不是节目正文的内容。
- 与学习目标关系弱的创业故事，除非它支撑技术判断。

正文大主题建议 4-6 个，每个大主题下可放 1-3 个小标题。超过 6 个大主题通常说明还没有聚焦；只有一层标题通常会显得结构松散。

## 段落写法

避免一整节都是大块自然段。正文必须有“大标题 + 小标题”两层结构：H2 负责全篇骨架，H3 负责具体主题。每节内部优先采用“短解释 + 小抓手”的节奏：

```markdown
## 二、<大主题>

### <小主题标题>

<一两句话交代这一节为什么重要。>

**<先说结论>**：<解释这个结论从哪里来，原文怎么论证，有什么限定。>

**<再拆机制>**：<如果有三层、两派、步骤、优先级，用列表或表格。>

**<最后给边界>**：<哪些是事实，哪些还只是预测或存疑。>
```

写作要求：

- 每个自然段尽量 2-5 行；长段要拆。
- 每段开头尽量有“这一段在讲什么”的抓手：加粗短句、冒号、问题句都可以。
- 每节应有收束句，但不要加“带走点”“学习要点”这类标签；需要收束时，直接把判断写成加粗句。
- 不要把所有内容都做成 bullet。需要理解的论证用 prose，方便查找的并列信息用结构。
- 第一个区块必须是 `## 播客核心内容`（独立 H2、不编号），正文大主题从「一、」开始编号。

## 主题重组规则

chunk 是按原文聊天顺序切出的消化单元；最终笔记的节是按主题组织的学习单元。合成时必须打散重组：把散落在不同 chunk、但属于同一学习主题的内容归拢到同一节里。

不要把 `chunk-001`、`chunk-002` 机械改写成最终笔记的第 1 节、第 2 节。也不要沿用“分层大纲 / 核心概念 / 关键论点 / 案例与证据 / 事实观点推测”这类平行分类大区；它们会把同一主题拆碎，导致重复且浅。

## 标注和边界

事实、预测、转写存疑、agent 补充不必单独拆成大区，但在行文里必须分得清。默认正文主体都是嘉宾观点的整理，不要每段重复归因。

推荐措辞：

- `可确认的是...`
- `这更像预测，不是已经发生的事实...`
- `这里的结论成立前提是...`
- `转写此处不稳，暂按上下文理解为...`

不要把观点升级成事实。必须保留限定词，例如“在某些情况下”“目前”“长期看”“可能”“倾向于”“在这个约束下”等。

agent 可以补少量无争议基础概念，但必须克制：补充内容要自然融入解释，不能写成嘉宾原话，也不能伪装成播客已明确支持的事实。不要补充对立观点，不要评价嘉宾观点对错。

**归属三分**：每段内容都要能归到「嘉宾原话 / 主持人引导 / 我的推论」三者之一。第三类最危险——写进正文，读者会当成嘉宾判断。处理方式二选一：删掉，或用「（按：…）」就地标出且全篇不超过三处。成段的推论不进正文，写进 `review/final-review.md` 的「判断层」，连同「这期改变了我什么判断」一起记三条以内。

## 时间戳规则

记录稿 `notes/notes.draft.md` 的关键定义、关键判断、关键例子和存疑处应挂 `[23:10]` 或 `[01:12:08]` 这类时间戳锚点，供 Phase 5 质检与日后回听核对。锚点不是每句话都挂，优先挂能帮助复核的结论点。

成稿 `notes/notes.md` **删除全部锚点**：锚点是核对工具，不是阅读内容，寿命止于 Phase 5。删除前另存一份同结构副本 `notes/notes.带时间锚点-溯源版.md`，需要核对时用它，正文保持干净。

时间戳只能来自 `source/clean-transcript.md`、`source/transcript.md`、`extraction/chunk-index.md` 或 `extraction/chunks/*.md`；没有时间戳就不要编造。

## 术语表规则

术语表要克制，只收真正影响理解的术语。每个术语包含：

- 术语名，必要时保留英文。
- 面向学习者的一句话解释。
- 它在本期为什么重要。

不要把所有英文词都放进术语表。术语表超过 10 个时，优先删掉只在文中出现一次、且不影响理解的词。

## 自检清单

写完后检查：

- 开头是否是 `## 播客核心内容`（独立 H2、不编号），两段说清处境与答案，并附不超过 5 行的取舍表？
- 正文是否有 H2 大标题和 H3 小标题两层结构？有没有只有一层标题导致结构发散？
- 正文大主题是否控制在 4-6 个？有没有信息太多太杂？
- 每节是否有简短小标题、加粗短句或问题句帮助理解？
- 每节是否有收束句，且没有“带走点 / 学习要点”这类标签？
- 是否有大段超过 5 行的自然段？有就拆。
- H1 是否是「主题 + 核心判断」，而不是播客原始标题？原标题与链接是否仍在元数据里？
- H2 是否是主题（可检索、不下结论），H3 是否是判断或真问题，而不是“核心概念”“关键论点”这类标签？
- 同一个主题是否散落在多个章节？有就合并。
- 是否把低价值背景写太多？有就压缩。
- 是否对照问题骨架清单，覆盖每个实质问题的核心回答？
- 正文是否默认以嘉宾观点展开，而不是反复写“嘉宾认为/嘉宾说”？
- 事实、预测、转写存疑、agent 补充是否能分辨？
- 是否保留了关键限定词和“为什么”？
- 关键定义/判断在 draft 里是否有可回溯时间戳、且无来源时不编造？
- 成稿是否已删除全部 `[mm:ss]`，并保留 `notes.带时间锚点-溯源版.md`？
- 随机抽 3 节，能否挂到核心内容节的塔尖下？
- 字数是否落在选定档位区间内？偏离超过 20% 有无写明原因？
- 核心术语异写计数是否为 0？同音词、简称全称混用、译名不统一各查一遍。
- 是否有超过 6 行的段落？段首句是否都在承担导航，而非铺垫？
- H3 是否都在 18 字以内？同层标题字数极差是否超过 2 倍？有无连续三个问句？
- 有没有把 agent 的推论写成嘉宾判断？「（按：…）」是否超过三处？
- 全文是否搜不到「一页读懂 / 一张表 / 一条线 / 带走点 / 本文 / 下面这张表 / 基于转写稿」？
- 是否删除了默认尾部的 `## 自测题`、`## 存疑与待核对`、`## 诚实边界声明`？
