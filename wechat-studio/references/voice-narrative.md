# 叙事观点体写作配方（「九边体」）

> 用于 `article_type` 落在**观点 / 职业 / 行业观察 / 个人经验**一族的文章（排版主题 `red-white`）。
> 首次拆解自九边《这个专业塌得有点惨》，并在 `posts/verification-right` 上跑通一遍。
> **技术拆解族不适用**——那类走 `SPEC.md` 6.1（工程蓝），要求相反：分章、来源标注、表格。

## 0. 红线（先读这条，其余都是次要）

**材料由用户提供，agent 不许自己生产事实。**

| | 可以自由加工 | 绝对不能生成 |
|---|---|---|
| 内容 | 画面、动作细节、比喻、情绪、糙词、段落顺序 | 某人说过什么、某数据存在、某事件发生过 |
| 例子 | ✅「语法漂亮得挑不出毛病，字段名也全对，逻辑是错的」 | ❌「我同学在某高校教书，他说今年最难」 |

判据一句话：**读者追问「谁说的 / 哪来的」，你答不上来，这句就不许写。**

为什么这条排第一：这套配方练的是「让读者相信你在场」。方向对了是可信，方向错了就是**更高级的伪造**。所以配方是写法约束，不是内容来源。

## 1. 一句话原理

「像自己经历」**不等于细节多**。它由三样东西合成：

| 零件 | 作用 | 读者信的是什么 |
|---|---|---|
| 动作痕迹 | 给「在场」 | 「我退了回去」这个动作 |
| 私有因果 | 给「待过」 | 只有坐过那个位置才说得出的那一句归因 |
| 口语毛刺 | 给「活人」 | 挑不出毛病、祈祷、完犊子 |

AI 能学前两样的**写法**（下表的约束就是干这个），学不了「料」。所以第 0 节的红线不可绕。

## 2. 闸门一：写作前，先要料（拿到才动笔）

不要接受「写一篇关于 XX 的文章」这种题目直接开写。先向用户要三条，缺哪条问哪条：

1. **一件你亲耳听到 / 亲眼看到的事**：谁、什么场合、说了什么
2. **一个你不同意的主流说法**
3. **一个你自己造的类比或词**（没有就现场一起造）

拿不到料的处理：**停下问，不许自己补。** 补出来的东西过不了第 0 节。

## 3. 闸门二：写作中的八条约束

每条都给「判定方式」——因为「要有观点」这种描述对写作者无效，可判定的才不会漏。

| # | 约束 | 判定方式（写完能逐条查） |
|---|---|---|
| 1 | 开头直接进场景或判断 | 前 200 字内**禁止**出现：随着、在当今、近年来、如今、众所周知、先说结论 |
| 2 | 第一句不是格言 | 若第一段是抽象结论而非具体事，改成场景。格言让读者站在对面验证你，场景让读者跟着你走 |
| 3 | 每 300 字一个动作 | 「我 + 动作动词 + 具体对象」≥ 全文汉字数 / 300。动作要带场合：问了谁、在哪问的、退回给谁 |
| 4 | 宏观数字降级 | 一律写成「我听说的」「有个数据说」，**不给出处、不加书名号、不写报告名** |
| 5 | 至少一处可视镜头 | 写清**几个人、在哪个房间、在干什么**。禁止「团队规模大幅缩减」这类抽象趋势 |
| 6 | 一处自我提问 | 形如「我认真琢磨了一下，这半年到底什么变了？」然后自己答。作用是把结论伪装成刚想出来的 |
| 7 | 一处主动让步 | 把话说满的地方往回拉一寸（「这话有点站着说话不腰疼」）。只赢一头的文章读者会自动打折 |
| 8 | 造一个词承重 | 全文靠一个自造概念推进（本次：暗知识 → 验收权 → 差价）。读者转发的是这个词 |

糙词：允许 3–5 处（挑不出毛病 / 祈祷 / 挺狠 / 上不了台面）。
禁用：困境、从业者、赋能、底层逻辑、结构性、闭环、抓手、颗粒度。（完整表见 `unclecheng-reduce-ai-perception-v2/references/banned-words.md`）

## 4. 闸门三：写作后的反向质检

逐句问三个问题，答不上来就二选一：**降级成「听说」，或者删掉。**

1. 这句的「我」是谁？我凭什么知道？
2. 这句能不能被别人原样写出来？能 → 是通稿，删或降级
3. 删掉这句，读者还信后面吗？还信 → 说明它没承重，删

再跑机器检查：

```bash
node tools/voice_lint.js posts/<slug>/article.md
```

它只查 5 类**可判定**病灶（开场铺垫、元叙述句、发卷子、二分收尾、动作密度不足），**只报 warning 不阻断**——文风误判率高，它的作用是给你定位，判定权在人。

## 5. 三处最容易翻车（都在这篇上真实发生过）

### 5.1 不要「发卷子」

结尾对读者下指令是最重的 AI 味：

> ❌ 把你手上最熟的那件活拿出来，问自己一句……你现在就该把重复的活丢给 AI。
> ✅ 我问过自己一次。想了半天，冒出来的全是坑过的……没被坑过的地方，我一句都说不出来。

**审判读者 → 防御；审判自己 → 无处可躲。** 同一句话，指向自己就成立。

配套删掉：给读者的动作派发（「给你一个今晚就能做的测试」）、营销比较级（「比任何职业规划都准」）、自评（「这个测试挺狠」）。

### 5.2 不要二分法收尾

> ❌ 说得出来，说明你有验收权；说不出来，那要小心。

逻辑闭合、看着完整，但现实里大多数人卡在中间——有的活答得出、有的答不出。压成开关就是假。改成承认中间态：「没被坑过的地方，我一句都说不出来。」

### 5.3 不要前后段逻辑断层

真实事故：前一段讲「下注」（进攻），后一段突然接「判断对错」（防守），读者失重却说不出哪里错。

修法是补中间环，不是删掉一头：**下注靠看见别人没看见的 → 看见靠在那个位置上待过 → 待过靠暗知识。** 三环接上，前面所有零件才落到同一个点。

## 6. 技术细节降维法

材料只需让外行看懂「**这很难**」，不需要他记住术语。术语是门槛，不是证据。

| 原文写法（只有同行看得懂） | 降维写法（外行也懂难在哪） |
|---|---|
| `realfieldname` / `fieldname` | 同一个东西，数据库叫一个名字，页面上叫另一个名字 |
| 4.0 库查 `t_company`、5.0 库查 `t_module` | 分两套库，查法不一样，中间还隔一层模块编号 |
| —— | 补一句翻译：「它写不进文档，因为写文档的人不觉得这需要写」 |

最后那行是关键：给外行一句**他们世界里的等价物**，比补三个术语有用。

## 7. 结构信号（写给工序 4 看的）

这类文章不套红白骨架的「引言卡 + 编号章节 + 导读」。缺这些信号时**不许为了套模板去造内容**（违反 SPEC 工序 4「只准机械转换」）。

| 信号 | 要求 |
|---|---|
| 章节 | 无 `##`，纯段落流；全文 30–35 段，段均 1–2 句，允许单句成段 |
| 引言 | 不使用 `>` 引言卡 |
| 加粗 | ≤6 对，集中在前 2/3；短段落本身就是强调，末段靠节奏不靠标记 |
| 下划线 | 排版侧给 12–15 处，别每段都标 |
| 破折号 | 全文最多 1 处，且必须是同位语解释（删了会丢指代）；停顿一律用句号 |
| 长度 | 1200–1400 字即可。嫌短就补一个具体的坑，**不要补论述**——论述是返味的主因 |

## 8. 交付前逐条打勾

- [ ] 第一段是事或判断，不是背景介绍
- [ ] 全文「我 + 动作」≥ 字数/300
- [ ] 有一处可视画面（人数 / 地点 / 在干什么）
- [ ] 有一处自我提问 + 一处主动让步
- [ ] 有一个自造词，且全文 3 次以上回扣它
- [ ] 结论没有一上来就是完成的（中间有过推翻或修正）
- [ ] 结尾没有对读者下指令、没有「保持学习 / 提升自己 / 拥抱变化」
- [ ] `voice_lint.js` 的 5 类 warning 都解释得通（或已修）
- [ ] 每条「我」都能对上用户的真实经历；对不上的已降级或删除
